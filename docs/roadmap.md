# 后续方向

当前功能与限制以 [支持范围](features.md) 为准。下面列出可以继续扩展的方向，尚未实现的部分不作为当前承诺。

| 方向 | 当前缺口 | 后续工作 |
|---|---|---|
| 数据相关输出 | 内建示例主要为 torch_musa nonzero | 为编译型后端定义输出大小计算、分配与上限校验接口 |
| 原生 Profiler | 没有独立子进程 GPU 采集器 | 核实厂商采集接口，保留真实设备事件和关联信息 |
| 编译期常量 | Triton、TileLang 仅有有限标量缩放示例 | 扩展常量类型、编译身份和缓存失效验证 |
| 类型与布局 | 各算子支持范围不同，复数及部分无符号类型受限 | 按后端补充可运行入口及正反例，扩大布局覆盖 |
| 动态 shape | 只在已声明的运行期参数与复用范围内有效 | 为更多算子记录真实编译产物与重新特化情况 |
| 工程搬迁 | 依赖、架构、ABI 仍需人工确认 | 增强目标环境检查，验证可搬移产物及交叉编译工具链 |
| kernel 仿真 | 官方 MUSA kernel 仿真无可运行接入 | 有可用依赖和厂商接口后再进行最小闭环验证 |
| 环境矩阵 | 未穷尽 GPU 架构和 SDK / 框架组合 | 在明确设备与依赖版本下逐项补充验收 |

多卡分布式、通用 backward、自动调优、GUI、数据库和长期稳定性认证继续排除在当前范围之外。扩展时应保持独立参考、可复现输入、真实设备证据及失败路径验证。
